Every organization in exIQtive has an organizational tree made of organizational objects. The tree is how you organize readiness across your company, and how employees receive their work.

## Organizational objects

| Object | Description | How to manage |
| --- | --- | --- |
| Position | Describes the roles and responsibilities an employee should have when they occupy it. Positions have roles attached. | [Positions](/organization/positions) |
| Role | A collection of responsibilities an employee needs to fulfill. Roles have responsibilities attached. | [Roles](/organization/roles) |
| Responsibility | A specific area of work. Responsibilities have Inspection Protocols attached. | [Managing responsibilities](/responsibilities/managing-responsibilities) |

## Attachments

- A responsibility can be attached to multiple roles.
- A role can be attached to multiple positions.
- A responsibility can also be attached directly to a position, skipping the role.
- When you assign an employee to a position, they're automatically assigned its roles and the responsibilities attached to those roles, plus any responsibilities attached directly to the position.

## Organizational object codes

Each position, role, and responsibility has a unique numeric code (like **#345**) within your organization. Use codes to find organizational objects quickly and precisely; you can search by code.

## Common questions

<AccordionGroup>
  <Accordion title="What's the difference between the organizational tree and departments?">
    The organizational tree describes the structural relationship between positions, roles, and responsibilities: the chain through which employees receive their work. Departments are a separate grouping that organizes positions into a visual hierarchy for navigation and reporting. Departments don't affect which responsibilities an employee holds. The one exception is [Fair Pay](/fair-reward/fair-pay): department placement drives Performance Scorecard and Bonus Eligibility Criteria for a position that doesn't have its own override.
  </Accordion>
  <Accordion title="How does an employee receive a responsibility?">
    Through their position: the employee is assigned to a position, the position has roles attached, and each role has responsibilities attached. Responsibilities can also be attached directly to the position. The employee automatically inherits all of them. Nothing is assigned to the employee directly.
  </Accordion>
  <Accordion title="Can the same role be used in multiple positions?">
    Yes. A role can be attached to any number of positions. Define it once with its responsibilities and reuse it wherever it's needed.
  </Accordion>
  <Accordion title="What is an organizational object code used for?">
    Each position, role, and responsibility has a unique numeric code (like #345). Codes make it easy to find and refer to specific objects precisely, especially in large organizations where names can be similar across departments.
  </Accordion>
  <Accordion title="Can a responsibility appear in more than one role?">
    Yes. If the same responsibility is in two roles that are both attached to the same position, the employee receives it twice, once for each role. Each role generates its own independent assignment.
  </Accordion>
</AccordionGroup>
